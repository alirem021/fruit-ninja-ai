# Fruit Ninja AI 🍉

یه ربات که فقط با دیدن صفحه‌ی مانیتور Fruit Ninja بازی می‌کنه. به کد بازی دست نمی‌زنم و هکش هم نمی‌کنم؛ مثل خود آدم، صفحه رو می‌بینه و ماوس رو تکون می‌ده.

بازی رو روی [Yandex Games](https://yandex.com/games/app/fruit-ninja-278766) توی Chrome اجرا می‌کنم. این پروژه رو برای ویدیوی یوتیوبم ساختم و کدش رو گذاشتم که هر کی خواست بازش کنه و دست ببره توش.

> فعلاً فقط روی **مک** کار می‌کنه (کنترل ماوس و گرفتن تصویر با Quartz انجام می‌شه). من روی یه مک M-series تستش کردم.

## ایده چیه؟

دو تا نسخه ساختم:

**نسخه ۱ (`v1_opencv.py`)** ساده‌ترین چیزی که به ذهنم می‌رسید: هر ثانیه یه اسکرین‌شات بگیر، با رنگ و حرکت میوه رو پیدا کن و بزن. جواب نمی‌ده، چون:
- میوه حدود یک ثانیه توی هواست و تا ربات بجنبه افتاده.
- لکه‌ی آب میوه هم‌رنگ میوه‌ست و ربات قاطیش می‌کنه.
- ترک‌های چوب پس‌زمینه رو بمب می‌بینه!

**نسخه ۲ (`v2_yolo.py`)** اینجا از یه مدل YOLO استفاده کردم که میوه و بمب رو تشخیص می‌ده. بعدش:
1. هر میوه رو بین فریم‌ها دنبال می‌کنه (ردیابی)
2. مسیر پرتابش رو حساب می‌کنه و می‌گه چند میلی‌ثانیه‌ی دیگه کجاست
3. خطی رو می‌کشه که بیشترین میوه رو ببره و به بمب نخوره
4. ضربه‌ی ماوس توی یه thread جدا زده می‌شه که حلقه‌ی دیدن منتظر نمونه

روی لپ‌تاپ خودم حدود ۵۰ تا ۶۰ فریم در ثانیه می‌گیره و از گرفتن عکس تا تصمیم گرفتن حدود ۱۵ میلی‌ثانیه طول می‌کشه.

## نصب

نیاز داری به: مک، Python 3.9 یا بالاتر، و Chrome.

```bash
git clone <آدرس این ریپو>
cd <اسم پوشه>

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

بار اول که اجرا کنی، مک می‌پرسه به ترمینال اجازه‌ی **Screen Recording** و **Accessibility** بدی. بده، وگرنه تصویر سیاه می‌گیره و ماوس تکون نمی‌خوره (بعد از دادن اجازه، ترمینال رو ببند و دوباره باز کن).

## اجرا (با مدل آماده)

مدل آموزش‌دیده توی `models/` هست، پس لازم نیست خودت چیزی آموزش بدی.

**۱. کالیبره کردن:** بازی رو توی Chrome باز کن و حالت **Classic** رو شروع کن (بمب داره). بعد:

```bash
python calibrate.py
```

ماوس رو ببر گوشه‌ی بالا-چپ ناحیه‌ی بازی و Enter بزن. بعد گوشه‌ی پایین-راست و دوباره Enter. اینجوری ربات می‌فهمه کجا رو نگاه کنه. نتیجه توی `config.json` ذخیره می‌شه.

> بعد از کالیبره پنجره‌ی Chrome رو جابه‌جا یا هم‌اندازه‌ش رو عوض نکن، وگرنه باید دوباره کالیبره کنی.

**۲. اول بدون زدن امتحان کن (`--dry-run`):** ماوس رو تکون نمی‌ده. فقط می‌بینه و یه فیلم دیباگ می‌سازه که ببینی چی تشخیص داده.

```bash
python v2_yolo.py --dry-run --record --seconds 40
```

۸ ثانیه وقت داری بری روی Chrome. خودت بازی کن و بعدش `runs/v2/.../debug.mp4` رو باز کن.

**۳. بازی واقعی:**

```bash
python v2_yolo.py --record
```

تا وقتی خودت قطعش نکنی ادامه می‌ده. هر ۵ ثانیه هم وضعیتش رو چاپ می‌کنه.

**قطع کردن:** ماوس رو ببر گوشه‌ی بالا-چپ **صفحه** (نه ناحیه‌ی بازی) یا Ctrl+C بزن.

### یه سری چیز که بدونی

- ربات فقط وقتی ضربه می‌زنه که Chrome بالاترین پنجره روی ناحیه‌ی بازی باشه. اگه یه پنجره‌ی دیگه بیاد جلو، می‌ایسته (که تصادفاً به برنامه‌ی دیگه‌ات چاقو نزنه).
- امتیاز بازی رو نمی‌خونه. فقط می‌تونی از روی فیلم و خود بازی ببینی چطور بوده.
- اگه ضربه‌ها دیر یا زود می‌رسن، `--lead` رو امتحان کن:

```bash
python v2_yolo.py --lead 0.03     # ضربه‌ها رو یه ذره جلوتر ببر
python v2_yolo.py --lead -0.03    # یا عقب‌تر
```

- `--fruit-conf` و `--bomb-conf` میزان اطمینان لازم برای قبول کردن تشخیصه (پیش‌فرض ۰.۳ و ۰.۲۵). بمب رو عمداً حساس‌تر گذاشتم، چون از دست دادنش گرون‌تره.

## مدل خودت رو آموزش بده

اگه پس‌زمینه یا چاقوی بازی‌ات فرق داره، یا می‌خوای بهتر بشه:

```bash
# ۱. بازی کن و فریم ضبط کن (۵ دقیقه، توی dataset/raw/ ذخیره می‌شه)
python record.py --name me --seconds 300

# ۲. فریم‌ها رو برچسب بزن
python label.py

# ۳. تبدیل به دیتاست و آموزش
python make_dataset.py
python train.py
```

توی `label.py` با ماوس دور میوه‌ها جعبه می‌کشی (کلید `1` میوه، `2` بمب). یه سری نکته که موقع برچسب زدن مهمه:

- فقط میوه‌ی **سالم و کامل** و بمب رو جعبه بزن. نصفه‌ها، لکه‌ی آب میوه و رد چاقو رو نه، تا مدل یاد بگیره اون‌ها میوه نیستن.
- فریمی که میوه‌ی کامل نداره رو فقط Enter بزن. همین فریم‌های خالی به مدل یاد می‌دن چی میوه نیست.
- جعبه رو تنگ دور میوه بکش.

دیتاست خودم رو (عکس‌های بازی) این‌جا نذاشتم. با ۵۸۵ فریم، ۶۲۲ میوه و ۱۵۲ بمب آموزش دادم و روی ۱۰۰ فریم که مدل ندیده بود امتحانش کردم:

| | precision | recall | mAP50 |
|---|---|---|---|
| میوه | ۰.۹۴ | ۰.۷۱ | ۰.۸۶ |
| بمب | ۰.۹۶ | ۱.۰۰ | ۰.۹۹۵ |

یعنی بمب تقریباً همیشه پیدا می‌شه، ولی حدود ۳ تا از هر ۱۰ میوه رو نمی‌بینه. بخشی‌ش به خاطر اینه که موقع برچسب زدن همه‌جا یکدست نبودم (بعضی میوه‌ها جعبه نخوردن، چند تا نصفه جعبه خوردن).

## فایل‌ها

| فایل | کارش |
|---|---|
| `calibrate.py` | مشخص کردن ناحیه‌ی بازی روی صفحه |
| `screen.py` / `mouse.py` | گرفتن تصویر و کشیدن ماوس |
| `v1_opencv.py` | نسخه‌ی اول (OpenCV) |
| `record.py` | ضبط فریم برای دیتاست |

| `make_dataset.py` | ساخت دیتاست train/val |
| `train.py` | آموزش YOLO |
| `tracker.py` | ردیابی و پیش‌بینی مسیر |
| `planner.py` | تصمیم این‌که از کجا ضربه بزنیم |
| `v2_yolo.py` | ربات نهایی |
| `models/` | مدل آموزش‌دیده |

## محدودیت‌ها

- فقط مک.
- فقط Classic رو تست کردم.
- اگه بین دورها تبلیغ بیاد، ربات نمی‌دونه ردش کنه و باید خودت بزنی.
- وقتی بازی تموم می‌شه، ربات هنوز اجرا می‌شه (کاری نمی‌کنه، چون چیزی تشخیص نمی‌ده) و باید خودت قطعش کنی.
- مسیر پرتابی رو با فیزیک ساده حساب می‌کنم. میوه‌هایی که تو دیتاستم نبودن (مثلاً آیتم‌های ویژه) رو نمی‌شناسه و ممکنه قاطی کنه.
